# Нерешённое: два правила выбора границы спорят между собой

Статус: ждёт решения (обсудить с ПМ).

В календаре сейчас уживаются два правила, и они противоречат друг другу.

## Правило 1 — за границу отвечает календарь

Левый календарь задаёт начало диапазона, правый — конец. Клик по дню меняет ту
границу, за которую отвечает календарь, в котором кликнули.

Зачем: без него день внутри диапазона всегда становился концом, потому что
react-day-picker смотрит на положение дня относительно диапазона, а не на то, где
кликнули. Диапазон 01.08.2018 — 17.09.2020, клик в левом календаре по 20.08.2018
делал эту дату концом, и диапазон схлопывался.

## Правило 2 — захват границы

Клик по дню, который является границей диапазона, не двигает её, а «берёт в
руки»: дальше каждый клик правит именно эту границу.

Выход из захвата: кликнуть по второй границе — тогда диапазон очищается целиком
и можно выбирать заново. Ещё захват отпускает шорткат или дата, введённая в поле.

Зачем: правило 1 не работает, когда диапазон целиком помещается в один месяц.
Диапазон 15.05 — 22.05, оба календаря показывают май и июнь. Чтобы сдвинуть конец
на 25.05, надо кликнуть по 25 мая — он есть только в левом календаре, а тот
отвечает за начало. В правом календаре июнь, майских чисел там нет. Конец
становится недостижимым.

## Где спорят

Спор всюду, где захваченная граница не совпадает с тем, за что отвечает
календарь. Это происходит и внутри одного календаря, и при переходе между ними.

Пример 1 — внутри одного календаря:

    диапазон 15.05 … 22.05, обе даты видны в левом календаре
    клик по 22 (конец)     — захватили конец
    клик по 18 в том же левом календаре

    по правилу 2:  15.05 … 18.05   (двигаем захваченный конец)
    по правилу 1:  18.05 … 22.05   (левый календарь = начало)

Пример 2 — при переходе в другой календарь:

    диапазон 15.05 … 22.05
    клик по 15 (начало)    — захватили начало
    клик по 10.06 в правом календаре

    по правилу 2:  22.05 … 10.06   (двигаем начало; оно ушло за конец,
                                    сработал обмен, начало 15.05 потеряно)
    по правилу 1:  15.05 … 10.06   (правый календарь = конец)

Сейчас побеждает правило 2: захват проверяется раньше.

## Варианты

1. Захват главный, правило календаря — запасное (действует, пока за границу не
   брались). Так работает сейчас.
2. Захват действует только в том календаре, где его взяли. Клик в другом
   календаре переводит правку по правилу 1.
3. Правило календаря главное всегда, захват убрать. Ломает узкие диапазоны —
   см. «Зачем» у правила 2.
4. Убрать правило календаря, двигать ближайшую к клику границу. Возвращает
   исходную жалобу: день внутри диапазона может стать концом, хотя кликнули в
   левом календаре.

## Побочный вопрос

При захвате границы и переносе её за другую границу концы меняются ролями:
диапазон 15.05 — 22.05, захватили начало, кликнули по 27.05 → получаем
22.05 — 27.05. Дата 15.05 исчезает, хотя её не трогали. Это поведение Blueprint,
оставлено намеренно, но стоит перепроверить вместе с выбором варианта выше.
